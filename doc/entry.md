### 现代 x86_64 操作系统（以 Linux 为例）的内核加载与启动地址分为‌实模式入口‌、‌解压后内核基址‌和‌长模式入口‌三个关键阶段，标准地址如下：

#### 核心地址标准
‌实模式入口地址‌：‌0x10000‌（1MB 处）。Bootloader 将 bzImage 头部加载至此，CPU 首先执行这里的 16 位实模式代码（arch/x86/boot/header.S 中的 _start）。
- ‌默认解压/加载基址‌：‌0x100000‌（1MB 处）。压缩的内核主体默认被加载并解压到物理地址 1MB 开始的位置。若启用 CONFIG_RELOCATABLE，该地址可动态调整，但 1MB 仍是传统标准对齐点。
- ‌64 位长模式入口‌：‌0x100000 + 偏移‌。解压完成后，内核跳转至 64 位保护模式入口 startup_64（位于 arch/x86/kernel/head_64.S），该符号的实际物理地址取决于最终加载基址，通常紧接在解压后的代码段起始处。‌‌
#### 启动流程关键节点
- ‌加载阶段‌：Bootloader（如 GRUB）将内核镜像加载到内存，设置 boot_params 结构体，并将执行权移交至 ‌0x10000‌。
- ‌初始化阶段‌：实模式代码完成硬件探测、A20 门开启及保护模式切换，随后加载 GDT 并跳转至 32 位保护模式代码（仍在低内存区域）。
- ‌解压与切换‌：32 位代码负责解压内核到目标地址（默认 ‌0x100000‌），构建早期页表，最后通过 ljmp 指令进入 ‌64 位长模式‌，执行 startup_64。
- ‌C 语言入口‌：汇编代码完成寄存器初始化后，调用第一个 C 函数 x86_64_start_kernel()，最终进入核心初始化函数 start_kernel()。‌‌
#### 特殊情况说明
‌EFI Stub 启动‌：若使用 UEFI 直接启动（EFI Boot Stub），内核作为 PE/COFF 映像被固件加载，入口点由 EFI 协议指定，但内部逻辑仍遵循上述解压和长模式切换流程，最终目标地址依然趋向于 ‌0x100000‌ 或其对齐位置。
‌KASLR 影响‌：若开启内核地址空间布局随机化（KASLR），实际加载基址会在启动时随机偏移，但‌逻辑入口点‌相对于基址的偏移量保持不变。‌‌

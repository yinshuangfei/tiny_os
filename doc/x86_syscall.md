# 系统调用过程
```
用户程序: mov $1, %rax    <-- 软件把号码放进 rax
          syscall          <-- 硬件触发

CPU 硬件: 1. 切换到 Ring 0
          2. 切换栈和页表
          3. 从 rax 读出数字 1  <-- 硬件固定读 rax
          4. 跳转到内核入口

Linux 内核: 1. 拿到数字 1
            2. 查表: table[1] = sys_write  <-- 软件查表
            3. 执行 sys_write
```

# 系统调用传参
系统调用号是硬件是固定从`寄存器`读取的。
## x86_64
在 64位 Linux (x86_64) 中，系统调用的参数传递遵循一套严格的 ABI（应用二进制接口）约定。
除了系统调用号放在 rax 中之外，最多支持 6个参数，它们被依次放入通用寄存器中。
如果系统调用需要的参数超过了 6 个（例如 mmap 或 clone 等复杂系统调用），第 7 个及以后的参数会被压入用户态的栈 (User Stack) 中。内核在需要时，会通过用户栈指针（保存在内核栈中）去读取这些额外的参数。

系统调用代码示例：
```
mov $1, %rax       ; 系统调用号: sys_write (1)
mov $1, %rdi       ; 第1个参数: fd = 1 (标准输出)
mov $buffer, %rsi  ; 第2个参数: buf 的地址
mov $1024, %rdx    ; 第3个参数: count = 1024
syscall            ; 触发系统调用

; 执行完毕后，rax 中存放返回值（写入的字节数或负的错误码）
```

| 架构 | 系统调用号寄存器 | 参数 1~6 的寄存器 |
| :--- | :--- | :--- |
| x86_64 | `rax` | `rdi, rsi, rdx, r10, r8, r9` |
| ARM64 | `x8` | `x0, x1, x2, x3, x4, x5` |
| RISC-V | `a7` | `a0, a1, a2, a3, a4, a5` |

## x86_32
（1）触发系统调用
在 32位 Linux 中，系统调用主要通过执行软中断指令 int 0x80 来触发。
（2）参数传递：全部使用寄存器
与 64位系统不同，32位 Linux 的系统调用最多只支持 6 个参数，且全部通过寄存器传递，不使用栈传递。
除了系统调用号放在 eax 寄存器中外，其余 6 个参数严格按照以下顺序放入寄存器：
| 参数顺序 | 对应寄存器 |
| :--- | :--- |
| 系统调用号 | `eax` |
| 第 1 个参数 | `ebx` |
| 第 2 个参数 | `ecx` |
| 第 3 个参数 | `edx` |
| 第 4 个参数 | `esi` |
| 第 5 个参数 | `edi` |
| 第 6 个参数 | `ebp` |
（3）返回值：eax
系统调用执行完毕后，内核同样会将结果（返回值或负的错误码）写入 eax 寄存器中返回给用户态。
（4）与64为对比

| 特性 | x86 32位 (i386) | x86 64位 (x86_64) |
| :--- | :--- | :--- |
| 触发指令 | `int 0x80` (或 `sysenter`) | `syscall` |
| 调用号寄存器 | `eax` | `rax` |
| 参数传递 | 6个寄存器 (`ebx, ecx, edx, esi, edi, ebp`) | 6个寄存器 (`rdi, rsi, rdx, r10, r8, r9`) |
| 超过6个参数 | 不支持 (32位最多6个参数) | 超过6个的参数压入用户栈 |
| 返回值 | `eax` | `rax` |


# syscall waitpid
在 Linux 里, waitpid 的第二个参数不是“裸的 exit code”，而是一个 status word（状态字），
低 8 位存退出码，高位还可能有“是否正常退出、是否被信号杀死”等信息。POSIX 提供了若干宏来
解析它，例如：
|宏|	含义|
|:---|:---|
|WIFEXITED(status)|子进程是否正常调用 exit() 退出|
|WEXITSTATUS(status)|若正常退出，取出退出码（0–255）|
|WIFSIGNALED(status)|是否被信号杀死|
|WTERMSIG(status)|若是信号杀死，取出信号编号|

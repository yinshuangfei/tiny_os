# 可以跨文件系统 rename 吗？
不可以。在 Linux 和类 Unix 系统中，rename 系统调用无法跨文件系统进行文件重命名或移动。


# 文件系统挂载多个 ext2 实例，是 vfs 管控，还是具体文件系统管控？
文件系统挂载多个实例，是由 VFS（虚拟文件系统）和具体文件系统协同管控的。
1. VFS 的管控职责（全局统筹与实例隔离）
全局挂载管理：当执行挂载命令时，VFS 会接管流程，为每一个挂载的 ext2 实例创建独立的 vfsmount 对象，并将其添加到系统的挂载点链表中。
维护独立超级块：VFS 会为每一个已挂载的 ext2 实例在内存中建立并维护一个独立的 VFS 超级块（super_block）。这些超级块记录了各自实例的设备标志符、块大小等核心信息，确保多个实例之间互不干扰1。
路径解析与分发：当应用程序访问某个 ext2 实例中的文件时，VFS 负责解析路径，并根据挂载层级将请求准确分发到对应的 ext2 实例上。
2. ext2 文件系统的管控职责（底层元数据与逻辑实现）
读取物理超级块：在 VFS 调用 ext2 的挂载函数后，ext2 会负责从对应的物理设备上读取其专属的超级块信息，获取该实例的块大小、inode 数量、空闲块列表等底层元数据。
实现专属操作：ext2 需要实现 VFS 约定的操作集（如 super_operations、inode_operations 等），以便 VFS 能够将标准的系统调用（如 read、write）正确“翻译”为 ext2 的底层操作逻辑。
管理物理存储：ext2 负责管理其自身实例在磁盘上的 inode 分配、数据块读写等具体细节。

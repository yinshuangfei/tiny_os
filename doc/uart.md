# 为什么要及时关闭发送中断?
因为 THR 空（THRE）在“没事可发”时几乎一直为真。

若发送中断一直开着，就会变成：
1. 发完最后一个字节，TX 缓冲空了
2. LSR.THRE 仍为 1 → 硬件认为“可以再发”
3. IER_THRE 若仍使能 → 立刻（或反复）报发送中断
4. ISR 进来一看：tx_buf 空，什么也不做，关中断或 EOI 返回
5. 若没关掉 IER → 马上又中断 → 死循环占满 CPU（中断风暴）

因此，没有待发数据时必须关掉 THRE 中断，有数据入队时再打开。

|	|接收 (RDA)	|发送 (THRE)|
|---|---|---|
|空闲时|通常无数据，不会狂报|空闲也常为“THR 空”，会狂报|
|策略|可以一直开着等数据|空闲必须关，有活再开|

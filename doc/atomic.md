### 多核 cpu 上，在一个核上执行一个原子操作，该原子操作能对其他核有效吗?
在多核 CPU 上，一个核上执行的原子操作绝对可以对其他核有效。这正是“原子操作”存在的核心
意义：保证多核/多线程环境下的数据一致性和内存可见性。如果原子操作不能跨核生效，那么现代
多核处理器就无法安全地进行并发编程了。
1. 硬件层面的缓存一致性协议（Cache Coherence）
多核 CPU 的每个核心通常都有自己的高速缓存（L1/L2 Cache）。当一个核执行原子操作
（如 atomic::fetch_add 或 compare_exchange）时，硬件会通过缓存一致性协议（最著名的
是 MESI 协议）来协调各个核心的缓存状态：
- 如果目标内存行（Cache Line）在其他核的缓存中处于“共享（Shared）”或“过期”状态，当前核会通过总线或片上网络（NoC）发送消息，强制其他核 invalidate（失效） 该缓存行。
- 这确保了其他核在下一次读取该内存地址时，必须重新从主存或当前持有最新数据的核的缓存中获取最新值。
2. 内存屏障与指令语义（Memory Barriers / Fences）
单纯的“不可分割”只是原子性（Atomicity），跨核有效还需要可见性（Visibility）和顺序性（Ordering）。
- 现代 CPU 为了性能会进行乱序执行（Out-of-Order Execution）和写缓冲（Store Buffer）。
- 原子操作在底层通常会隐式或显式地插入内存屏障指令（如 x86 的 LOCK 前缀，ARM 的 DMB/DSB 指令）。
- 这些屏障会强制 CPU 将写缓冲区（Store Buffer）中的数据刷新（Flush）到缓存或内存中，并阻止后续的读写操作重排到该原子操作之前。这就保证了其他核能“及时看到”这个修改。
3. 硬件级别的锁机制
在底层汇编层面，针对内存的原子操作通常会转化为带有特殊前缀的指令。例如在 x86 架构中：
LOCK ADD [mem], reg
LOCK 前缀会锁定总线或锁定对应的缓存行（Cache Locking），在整个原子操作期间，阻止其他核心访问该内存区域，直到操作完成并同步缓存。
